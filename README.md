# 신한 자영업 경영지원 컨설팅 (PPT 작성용 README)

이 문서는 발표 자료(PPT) 작성을 위해, 실제 구현 코드 기준으로 서비스 기획/데이터/지표/화면 흐름을 정리한 문서입니다.  
숫자·조건·동작은 `web_app.py`, `src/risk_engine.py`, `routers/operating_business.py`, `routers/map_api.py`, `src/data_loader.py` 기준입니다.

---

## 1) 왜 이 비즈니스가 필요한가

### 문제 정의
- 기존 상권 서비스는 **상권 통계 조회**는 가능하지만, 점포 운영자가 체감하는 질문(지금 써도 되는 돈, 대출 부담, 보험 공백, 이번 달 실행 과제)에 바로 답하기 어렵습니다.
- 현장에서 필요한 판단은 단일 지표가 아니라 **매출·비용·현금·부채·보험·경쟁**을 함께 보는 구조입니다.
- 특히 소상공인은 “데이터는 많지만 실행 우선순위가 모호”한 상태가 반복됩니다.

### 서비스가 해결하는 방식
- 단계형 흐름으로 진입장벽을 낮춤: `홈 → 사용자 유형 → 상권/업종 → 조건 입력 → 결과 대시보드`.
- 결과를 “조회”가 아니라 “행동”으로 연결:
  - 종합 점수 + 세부 점수
  - 탭별 원인 해석
  - 30일 실행 플랜
  - 신한 그룹 연계 점검 경로
- 금융상품 확정 추천이 아니라 **점검·상담 필요성 안내** 수준으로 안전하게 설계.

### 기대 효과(발표 포인트)
- 점포주: “이번 달 어디부터 손볼지”를 빠르게 결정.
- 금융기관: 데이터 기반 상담 사전진단 도구로 활용 가능.
- 내부 기획/운영: 동일 UI에서 창업/운영/금융점검 시나리오를 통합 검증.

## 2) 데이터: 무엇을 쓰고, 어떻게 관리하는가

## 데이터 소스(코드 반영 기준)

### 공공 데이터
- 서울시 상권분석서비스: 추정매출, 점포, 유동인구, 상주/직장인구, 상권변화, 집객시설, 영역.
- 소상공인시장진흥공단 상가정보: 위경도 포함 점포 데이터(경쟁점 지도).
- KOSIS 기업생멸행정통계: 업종 생존율.
- 한국부동산원 임대동향: 임대 지표.

### 서비스 내부(운영 사업자/금융점검)
- `routers/operating_business.py`는 현재 데모 목적의 목업 프로필(`MOCK_PROFILE`, `STORE_OVERLAYS`)을 사용.
- 카드 매출/지출, 은행 입출금, 대출, 보험, 상권 비교치를 통합 JSON으로 제공.

## 적재/조회 방식
- CSV 인코딩 자동 감지: `utf-8-sig → cp949 → euc-kr → utf-8`.
- `lru_cache` 기반 메모리 캐시로 반복 로드 비용 절감.
- 대용량은 DuckDB 쿼리 함수 병행(`query_sales_by_area_industry`).
- 좌표는 EPSG:5181 → WGS84 변환 후 지도 사용.

## 업데이트 주기(허구 없이 명시)
- **현재 코드 기준 자동 스케줄러는 없음**.
- 데이터는 `data/` 경로 파일을 교체/추가한 뒤 서버 재시작 시 반영되는 운영 형태.
- 분기/월 단위 최신화는 데이터 공급기관 배포 주기에 맞춰 수동 반영하는 구조.
- 즉 PPT에는 “**자동 배치 구축 전 단계(PoC), 수동 업데이트 운영**”으로 표기하는 것이 정확합니다.

## 3) 웹 개발 흐름과 사용자 도움 방식

## 기술 구조
- 백엔드: FastAPI (`web_app.py`에서 라우터 통합).
- 프론트엔드: `templates/index.html` + `static/js/app.js` + `static/js/operating_business.js` + `static/js/financial_check.js`.
- 차트: Chart.js.
- 지도: Leaflet/OSM 기반 경쟁점 표시 + 외부 검색 API 연계.

## 사용자 흐름(운영자 시나리오)
1. 데이터 연결 동의.
2. 사업장 선택.
3. 통합 프로필 미리보기.
4. 최소 추가 입력 후 AI 경영진단 실행.
5. 결과 탭에서 종합 요약/세부 분석/실행 플랜 확인.

## “어떤 조건에서 어떻게 동작하는지” 핵심 규칙

### 경쟁점 반경 확장 규칙 (`map_api.py`)
- 기본 반경 내 동일 업종이 5곳 이하이면 500→750→1000→1500→2000→3000→5000m로 확장.
- 반경 1km 내 동일 업종 0건이면 행정동→자치구 단위로 참고군 확장.
- 동일 업종이 부족하면 반경 2km 내 타업종 참고군도 별도 제공.

### 실행 플랜 생성 규칙 (`operating_business.py`)
- `action-plan` 호출 시 1~4주 과제를 생성해 반환.
- 프론트에서 이전 플랜과 비교해 “신규 추가/제외 항목”을 리포트형으로 표시.
- 즉, 단순 목록이 아니라 “왜/무엇이 달라졌는지”를 실행 탭에서 확인 가능.

### 사용 가능 금액 판단 규칙
- 운영 분석:
  - `available_cash = 현재잔액 + 월매출 - 30일예정지출 - 안전자금 - 세금예비금`
- 금융점검 분석:
  - `available_cash = 현재잔액 + 월입금 - 30일예정지출 - 안전자금 - 세금예비금 - 월보험료`
- 사용자 지출 입력이 사용가능금액 초과 시 “비추천” 응답.

## 4) 지표 기준(발표용 핵심)

## 4-1. 세부 점수(8개, `risk_engine.py`)

1. 상권 매력도 (Positive)  
   - 평균매출, 유동인구, 상주/직장인구를 0~100 정규화 후 가중합.
2. 매출 성장성 (Positive)  
   - 1년 변화율(60%) + 최근 1분기 변화율(40%).
3. 경쟁 강도 (Negative)  
   - 점포 증가율, 반경 경쟁점 수, 유사업종 밀도.
4. 유동인구 적합도 (Positive)  
   - 유동인구 수준 + 최근 트렌드.
5. 점포 생태계 안정성 (Positive)  
   - 폐업률(역정규화) + 상권변화지표.
6. 업종 생존성 (Positive)  
   - KOSIS 생존율 기반.
7. 임대료·고정비 부담 (Negative)  
   - 임대지표 변동 기반.
8. 부채 체력 (Positive)  
   - 이자부담률(역), 고정비부담률(역), 현금보유개월(정).

## 4-2. 신한 연계 진단 점수(4개)
- 은행 점검 필요성, 카드 매출관리 활용도, 보험 점검 필요성, 성장지원 가능성.
- 공통 원칙: 확정 추천이 아니라 **점검 우선순위/상담 필요성**을 표시.

## 4-3. 사용자 유형별 최종 점수
- 창업 예정자: 창업 적합도.
- 운영 중 사업자: 운영 안정도.
- 기존 매장 확장 검토: 확장 적합도.
- 금융/보험/비용 구조 점검: 재무 체력 점수.
- 경쟁/임대 항목은 역점수(높을수록 위험)를 반영해 최종 가중합 계산.

## 4-4. 조기경보(Warning) 기준
- 최근 1분기 매출 -10% 이하.
- 상권 평균 대비 매출 70% 미만.
- 동일 업종 점포 1년 +20% 초과.
- 유동인구 최근 분기 -10% 이하.

## 5) 화면 기획(슬라이드로 옮기기 쉬운 형태)

## 슬라이드 구성 추천

1. 서비스 한 줄 정의  
   - “상권 조회를 넘어, 점포별 실행 결정을 돕는 단계형 경영진단.”

2. 왜 필요한가  
   - 데이터 과잉 vs 실행 부족 문제.

3. 사용자 흐름  
   - 5단계 Wizard + 결과 탭 구조.

4. 데이터 아키텍처  
   - 공공데이터 + 내부 프로필 + 캐시/좌표변환.

5. 지표 체계  
   - 8개 리스크/적합도 + 4개 금융연계 + 최종 점수.

6. 조건별 동작 예시  
   - 반경 확장, 사용가능금액 계산, 실행플랜 생성/비교.

7. 결과 화면 예시  
   - 종합요약 대시보드(9개 카드), 실행플랜 리포트형 블록.

8. 운영 방식/한계  
   - 자동 배치 미구축, 수동 데이터 갱신(PoC 단계).

## 6) PPT 본문에 바로 넣을 수 있는 문장

- “이 서비스는 상권 지표를 보여주는 것을 넘어, 점포가 이번 달에 실행할 과제를 제시하는 데 목적이 있습니다.”
- “현재 버전은 공공데이터와 목업 금융데이터를 결합한 PoC이며, 데이터 업데이트는 수동 반영 방식입니다.”
- “핵심 지표는 매출·경쟁·현금흐름·부채·보험을 통합해 계산하며, 금융상품은 확정 추천이 아닌 점검 우선순위 중심으로 안내합니다.”
- “실행 플랜 화면은 생성 근거와 이전 대비 변경점을 함께 제시해, 결과 해석에서 실행으로 이어지도록 설계했습니다.”
