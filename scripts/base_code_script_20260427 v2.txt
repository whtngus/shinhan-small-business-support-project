공공데이터 기반 자영업자 경영지원 웹서비스를 개발한다.

모든 개발환경은 anaconda shinhan 가상환경 내에서 실행한다. 
 
이 서비스는 단순 챗봇이 아니다. 사용자가 아무 말이나 입력하면 챗봇이 답하는 구조가 아니라, 실제 금융회사 웹서비스처럼 단계형 컨설팅 화면을 제공해야 한다. 전체 서비스는 “상권 분석 → 사업 조건 입력 → 창업/운영 진단 → 금융·카드·보험·성장지원 필요성 도출 → AI 종합 리포트 → 상담/점검 연결” 흐름으로 설계한다.

서비스 목표는 사용자가 창업 또는 운영과 관련해 지역, 상권, 업종, 예상 자금, 월매출, 임대료, 대출 필요금액 등을 입력하면 공공데이터 기반으로 상권 현황, 매출 가능성, 경쟁점, 유동인구, 업종 생존율, 임대료 부담, 금융 필요성, 보험 필요성, 카드 활용 전략, 성장지원 가능성을 종합 분석해주는 것이다.

초기 버전은 실제 신한 내부 데이터를 사용하지 않는다. 로컬 ./data 폴더의 공공데이터와 합성 점포 데이터를 사용한다. 향후 고객 동의와 법적 검토를 거쳐 신한은행, 신한카드, 신한라이프, 신한투자증권 서비스와 연계 가능한 구조로 설계한다.

개발은 바로 코드부터 작성하지 말고 먼저 README.md를 작성한다. README에는 서비스 개요, 폴더 구조, 데이터 구조, 실행 방법, TODO 리스트, 남은 이슈, 데이터 정비 현황, API 목록, 화면 구성 계획을 정리한다. 이후 TODO를 하나씩 완료하면서 개발한다.

금지사항은 다음과 같다. Streamlit 사용 금지, Gradio 사용 금지, 전체 서비스를 자유발화 챗봇으로 만들지 말 것, 대용량 CSV를 매 요청마다 직접 읽지 말 것, API Key나 데이터 경로를 코드에 하드코딩하지 말 것, 금융상품을 확정 추천하거나 대출 가능 여부/금리를 단정하지 말 것.

이 서비스는 실제 기업 서비스처럼 보여야 한다. 화면은 금융회사 B2B SaaS 스타일로 구성한다. 카드형 대시보드, 단계형 입력 폼, 지도 뷰, 차트, 리포트, 신한 서비스 연결 카드가 있어야 한다. 지도상 웹 뷰도 반드시 포함한다. 지도는 Leaflet 또는 MapLibre를 사용한다.

기술 스택은 다음을 기준으로 한다.
프론트엔드: 회사 비지니스 화면을 반영 
백엔드: FastAPI, Python, Pydantic
데이터 처리: pandas, DuckDB
LLM/RAG: Gemini 무료 API 우선 사용, 실패 시 템플릿 기반 리포트 fallback
데이터 저장: 초기에는 DuckDB 사용
설정관리: .env 또는 config.yaml 사용

설정값은 반드시 설정파일로 분리한다.
.env 또는 config.yaml에 다음 값을 분리한다.

DATA_DIR=./data
DUCKDB_PATH=./data/app.duckdb
GEMINI_API_KEY=
GEMINI_MODEL=gemini-1.5-flash 또는 사용 가능한 무료 모델
ENABLE_LLM_REPORT=true
ENABLE_RAG=false
DEFAULT_REGION=서울
DEFAULT_YEAR_QUARTER=20254
FRONTEND_API_BASE_URL=http://localhost:8000
RISK_SCORE_WEIGHT_SALES=0.25
RISK_SCORE_WEIGHT_COMPETITION=0.20
RISK_SCORE_WEIGHT_CLOSURE=0.15
RISK_SCORE_WEIGHT_POPULATION=0.15
RISK_SCORE_WEIGHT_SURVIVAL=0.15
RISK_SCORE_WEIGHT_RENT=0.10

API Key, 데이터 경로, 모델명, DB 경로, 점수 가중치는 코드에 하드코딩하지 않는다.

서비스 흐름은 다음과 같이 설계한다.

1. 홈 화면

사용자에게 “창업 컨설팅 시작하기”, “운영 중인 매장 진단하기”, “샘플 리포트 보기” 버튼을 제공한다. 홈 화면 문구는 자영업자가 감이 아니라 데이터로 창업과 운영을 판단할 수 있도록 돕는 서비스라는 방향으로 작성한다.

홈 화면 핵심 문구 예시는 다음과 같다.
“자영업 창업과 운영, 감이 아니라 데이터로 판단하세요. 상권, 유동인구, 경쟁점, 매출 가능성, 임대료 부담, 업종 생존율을 분석하고 사업에 필요한 자금, 보험, 카드 매출관리, 성장지원 방향까지 한 번에 점검해드립니다.”

샘플 리포트 보기는 발표와 데모를 위해 반드시 제공한다. 사용자가 입력하지 않아도 결과 화면을 체험할 수 있어야 한다.

2. 사용자 유형 선택 화면

사용자는 다음 중 하나를 선택한다.
- 창업 예정자
- 운영 중인 사업자
- 기존 매장 확장 검토
- 금융/보험/비용 구조 점검

선택 결과에 따라 이후 입력폼과 결과 화면을 다르게 보여준다.

창업 예정자는 입지 적합도, 업종 적합도, 예상 매출 가능성, 경쟁 강도, 초기 필요자금, 대출 상담 필요성, 필수 보험 점검, 카드 가맹점 준비사항을 중심으로 결과를 제공한다.

운영 중 사업자는 상권 평균 대비 내 점포 위치, 매출 개선 포인트, 시간대별 운영 전략, 경쟁점 변화, 고정비 부담, 대출 상환 부담, 카드 매출관리 필요성, 보험 보장 공백 점검을 중심으로 결과를 제공한다.

확장 검토 사용자는 후보 상권 비교, 기존 점포 대비 유사 상권 추천, 확장 적합도, 추가 자금 필요성, 법인 전환/성장지원 가능성을 중심으로 결과를 제공한다.

금융 점검 사용자는 이자부담률, 고정비부담률, 현금보유개월 수, 매출 감소 시 생존기간, 대환/운영자금 상담 필요성, 보험 점검 필요성을 중심으로 결과를 제공한다.

3. 지역/상권/업종 선택 화면

사용자는 자치구, 행정동, 상권 구분, 상권명, 서비스 업종명을 선택한다. 서울시 상권분석서비스의 상권코드, 상권명, 서비스업종명을 기준으로 필터를 구성한다. 검색형 드롭다운을 제공한다.

사용자에게 보이는 문구는 다음과 같이 작성한다.
“분석할 상권과 업종을 선택하세요. 선택한 상권의 매출, 점포 수, 유동인구, 경쟁점, 생존율, 임대료 지표를 기반으로 창업·운영·금융 컨설팅 결과를 제공합니다.”

검색창 예시는 “강남 카페”, “홍대 음식점”, “종로 미용실”처럼 제공한다. 단, 검색어 입력 후에는 내부적으로 후보 상권/업종 리스트를 보여주고 사용자가 정형 필터를 선택하게 한다. 자유발화 챗봇처럼 바로 답변하지 말고 검색 보조 기능으로만 사용한다.

4. 사업 조건 입력 화면

창업 예정자는 다음을 입력한다.
- 보유 자금
- 필요 대출금
- 예상 월 임대료
- 예상 인테리어/시설비
- 예상 직원 수
- 예상 월 인건비
- 예상 점포 면적
- 예상 객단가
- 예상 하루 고객 수
- 운영 형태: 홀, 배달, 테이크아웃, 복합

운영 중 사업자는 다음을 입력한다.
- 월 평균 매출
- 월 임대료
- 월 인건비
- 원가율
- 기존 대출잔액
- 평균 금리
- 월 상환액
- 현금 보유액
- 주요 영업시간
- 주요 고객층

입력 부담을 줄이기 위해 간편 입력, 상세 입력, 샘플 점포로 체험 세 가지 모드를 제공한다. 간편 입력은 월매출, 임대료, 인건비, 대출잔액, 현금보유액만 받는다. 나머지는 상권/업종 평균 또는 합성 목업값으로 자동 생성한다.

사용자가 입력하지 않아도 샘플 점포로 체험할 수 있게 한다. 버튼명은 “샘플 점포로 분석하기”로 한다.

5. 분석 로딩 화면

사용자가 분석 버튼을 누르면 바로 결과만 보여주지 말고, 어떤 데이터를 분석하는지 1~2초 정도 보여준다. 발표용으로도 중요하다.

문구 예시는 다음과 같다.
“선택하신 상권과 업종을 분석하고 있습니다.”

분석 중인 데이터는 체크리스트로 보여준다.
- 서울시 상권 추정매출
- 점포 수 및 개·폐업 현황
- 길단위 유동인구
- 상주인구·직장인구
- 집객시설
- 상권변화지표
- 업종 생존율
- 주변 경쟁점
- 임대료·부동산 지표
- 입력한 사업 조건

6. 결과 화면 전체 구조

결과 화면은 금융권 대시보드형으로 구성한다. 한 페이지에 요약 정보가 충분히 들어가되, 탭 구조로 상세 내용을 나눈다.

상단에는 다음을 표시한다.
- 선택 상권
- 선택 업종
- 사용자 유형
- 분석 기준 분기
- 종합 판정

핵심 카드에는 다음을 표시한다.
- 창업 적합도
- 매출 잠재력
- 경쟁강도
- 유동인구
- 임대료 부담
- 업종 생존율
- 금융 점검 필요성
- 보험 점검 필요성
- 카드 활용도
- 성장지원 가능성

하단 탭은 다음으로 구성한다.
- 상권 요약
- 매출·점포 추이
- 경쟁점 지도
- 자금·손익분기점
- 신한 서비스 연결
- AI 리포트

7. 상권 종합진단 화면 또는 상권 요약 탭

선택 상권과 업종에 대해 다음을 보여준다.
- 추정매출
- 매출건수
- 점포 수
- 개업 점포 수
- 폐업 점포 수
- 프랜차이즈 점포 수
- 유동인구
- 상주인구
- 직장인구
- 집객시설
- 상권변화지표
- 소득소비
- 업종 생존율
- 임대료/부동산 지표

숫자만 보여주지 말고 해석 문구를 함께 제공한다.

예시 문구:
“해당 상권은 직장인구와 점심시간 유동인구가 높은 오피스형 상권입니다. 커피전문점 업종의 추정매출은 높은 편이나, 동일 업종 점포 수와 프랜차이즈 비중도 높아 경쟁강도가 강합니다. 초기 창업자는 일반 카페보다 테이크아웃, 디저트 특화, 오후 시간대 객단가 상승 전략이 필요합니다.”

8. 매출·점포 추이 탭

차트 중심 화면으로 구성한다.
- 분기별 추정매출
- 분기별 매출건수
- 분기별 점포 수
- 개업/폐업 점포 수
- 시간대별 매출
- 요일별 매출
- 유동인구 추이

차트만 보여주지 말고 비교 문구를 넣는다.
예시:
“최근 4개 분기 동안 상권 매출은 증가했지만, 동일 업종 점포 수도 함께 증가했습니다. 이는 시장 수요는 존재하지만 경쟁도 동시에 강해지고 있음을 의미합니다.”

9. 경쟁점 지도 화면 또는 경쟁점 지도 탭

소상공인시장진흥공단 상가정보의 위도/경도를 사용한다. 동일 업종 점포를 지도에 표시한다. 선택 상권 또는 목업 점포 기준으로 반경 300m, 500m, 1km 내 경쟁점 수를 계산한다. 프랜차이즈/비프랜차이즈 구분이 가능하면 표시한다. 지도는 Leaflet 또는 MapLibre를 사용한다.

기능은 다음과 같다.
- 동일 업종 점포 지도 표시
- 반경 300m 경쟁점 수
- 반경 500m 경쟁점 수
- 반경 1km 경쟁점 수
- 업종별 밀집도
- 프랜차이즈 여부 표시 가능 시 표시

사용자 문구 예시:
“선택 상권 반경 500m 내 동일 업종 점포가 37개 있습니다. 동일 자치구 평균 대비 경쟁점 밀도가 높은 편입니다. 가격 경쟁보다는 메뉴 차별화와 재방문 고객 관리 전략이 필요합니다.”

신한카드 연결 명분도 함께 제공한다.
“경쟁점이 많은 상권에서는 신규 고객 확보보다 재방문율 관리와 카드 프로모션 전략이 중요합니다.”

10. 창업/운영 적합도 화면

다음 점수를 계산한다.
- 창업 적합도
- 매출 잠재력
- 경쟁강도
- 유동인구 적합도
- 임대료 부담
- 업종 생존율
- 상권변화 안정성

등급은 다음으로 표시한다.
80~100 추천
60~79 조건부 추천
40~59 신중 검토
0~39 비추천

점수는 단순 숫자만 보여주지 말고 근거를 함께 제공한다. 예를 들어 경쟁강도가 높으면 동일 업종 점포 수, 반경 내 경쟁점 수, 프랜차이즈 비중을 근거로 설명한다.

11. 자금·손익분기점 탭

이 화면은 신한은행과 연결되는 핵심 화면이다.

입력 또는 계산 항목은 다음과 같다.
- 예상 월매출
- 월 임대료
- 월 인건비
- 원가율
- 기타 고정비
- 대출잔액
- 금리

금융상품을 확정 추천하지 말고 “상담 필요”, “점검 필요”, “검토 가능” 수준으로 표현한다.

Gemini 호출 실패 시 템플릿 기반 리포트를 반환한다.

RAG를 사용할 경우 대상 문서는 README, 데이터 딕셔너리, 점수 산식 설명, 서비스 설명 문서로 제한한다.
사용자 개인정보나 실제 금융정보는 RAG 문서에 넣지 않는다.

18. 차별화 방향

서울시 상권분석서비스는 상권 데이터 공급원이다. 우리 서비스는 상권 데이터 기반 경영 컨설팅 엔진이다.

기존 서비스는 “이 상권의 상태”를 보여준다. 우리 서비스는 “이 상권에서 사용자의 점포가 어떻게 창업하고, 운영하고, 자금을 조달하고, 보험으로 리스크를 막고, 성장할 수 있는지”를 제안한다.

핵심 차별점:
1. 상권 분석이 아니라 내 점포 관점의 창업/운영 적합도를 계산한다.
2. 부채 체력과 현금흐름 시뮬레이션을 제공한다.
3. 동일 업종 경쟁점 지도와 반경 분석을 제공한다.
4. AI 리포트로 실행 전략을 제공한다.
5. 향후 신한은행, 신한카드, 신한라이프, 신한투자증권 서비스와 연결할 수 있다.

19. 데이터 로드 구조

데이터 로드 구조를 먼저 구현한다.

먼저 backend/scripts/01_preview_data.py를 작성한다.
이 스크립트는 ./data 아래 JSON을 제외한 CSV, XLSX, XLS 파일을 전부 찾고, 각 파일별로 2줄 preview를 출력한다.
CSV는 utf-8-sig, cp949, euc-kr, utf-8 순서로 읽는다.
Excel은 모든 시트를 순회하되, 각 시트의 상위 2줄만 출력한다.
파일명, 인코딩, 컬럼 수, 컬럼 목록, 2줄 샘플을 출력한다.

아래 코드를 참고해서 구현한다.

from pathlib import Path
import pandas as pd

DATA_DIR = Path("./data")

pd.set_option("display.max_columns", None)
pd.set_option("display.max_colwidth", 80)
pd.set_option("display.width", 300)

files = sorted([
    *DATA_DIR.rglob("*.csv"),
    *DATA_DIR.rglob("*.xlsx"),
    *DATA_DIR.rglob("*.xls"),
])

files = [f for f in files if f.suffix.lower() != ".json"]

print(f"대상 파일 수: {len(files)}")

def read_csv_preview(path, n=2):
    for enc in ["utf-8-sig", "cp949", "euc-kr", "utf-8"]:
        try:
            return pd.read_csv(path, nrows=n, encoding=enc, low_memory=False), enc
        except Exception:
            pass
    return None, None

for i, path in enumerate(files, start=1):
    print("\n" + "=" * 120)
    print(f"[{i}] {path}")
    print("=" * 120)

    try:
        if path.suffix.lower() == ".csv":
            df, enc = read_csv_preview(path, n=2)
            if df is None:
                print("CSV 로드 실패")
                continue

            print(f"형식: CSV / encoding={enc} / columns={len(df.columns)}")
            print("컬럼:", list(df.columns))
            print(df.head(2).to_string(index=False))

        else:
            xls = pd.ExcelFile(path)
            print(f"형식: Excel / sheets={len(xls.sheet_names)}")
            print("시트:", xls.sheet_names)

            for sheet in xls.sheet_names:
                print(f"\n--- Sheet: {sheet} ---")
                df = pd.read_excel(path, sheet_name=sheet, nrows=2)
                print(f"columns={len(df.columns)}")
                print("컬럼:", list(df.columns))
                print(df.head(2).to_string(index=False))

    except Exception as e:
        print("로드 실패:", repr(e))

20. JSON 변환 스크립트

두 번째로 backend/scripts/02_convert_json_to_csv.py를 작성한다.
이 스크립트는 ./data 아래 json 확장자가 있는 경우 같은 이름의 csv로 변환한다.
서울 열린데이터광장 JSON 형식인 DESCRIPTION, DATA 구조를 처리한다.
DESCRIPTION의 영문 컬럼명은 DATA의 소문자 컬럼과 매핑해서 한글 컬럼명으로 변경한다.

아래 코드를 참고해서 구현한다.

from pathlib import Path
import json
import pandas as pd

DATA_DIR = Path("./data")

json_files = list(DATA_DIR.rglob("*.json"))

print(f"JSON 파일 수: {len(json_files)}")

for json_path in json_files:
    print(f"\n처리 중: {json_path}")

    with open(json_path, "r", encoding="utf-8") as f:
        obj = json.load(f)

    if isinstance(obj, dict) and "DATA" in obj:
        df = pd.DataFrame(obj["DATA"])
        desc = obj.get("DESCRIPTION", {})
        rename_map = {k.lower(): v for k, v in desc.items()}
        df = df.rename(columns=rename_map)

    elif isinstance(obj, list):
        df = pd.DataFrame(obj)

    else:
        df = pd.DataFrame([obj])

    csv_path = json_path.with_suffix(".csv")
    df.to_csv(csv_path, index=False, encoding="utf-8-sig")

    print(f"저장 완료: {csv_path} / shape={df.shape}")

23. 점수 체계 및 진단 지표 설계

초기 버전은 설명 가능한 룰 기반 점수로 구현한다. 단일 위험점수 하나만 제공하지 말고, 사용자가 창업·운영·금융·보험·카드·성장지원 관점에서 자신의 상태를 이해할 수 있도록 여러 개의 세부 지표를 함께 제공한다.

점수 체계는 크게 3단계로 구성한다.

첫째, 최종 종합점수다.
최종 종합점수는 사용자의 창업 또는 운영 의사결정을 돕는 대표 점수다. 사용자 유형에 따라 이름을 다르게 표시한다.

창업 예정자에게는 “창업 적합도”로 표시한다.
운영 중 사업자에게는 “운영 안정도” 또는 “경영위험도”로 표시한다.
확장 검토 사용자에게는 “확장 적합도”로 표시한다.
금융 점검 사용자에게는 “재무 체력 점수”로 표시한다.

둘째, 세부 진단 점수다.
세부 진단 점수는 최종 종합점수의 근거로 사용된다. 최소 다음 지표를 제공한다.

1. 상권 매력도
상권의 전체 수요와 성장 가능성을 평가한다.
활용 데이터는 추정매출, 매출건수, 유동인구, 상주인구, 직장인구, 집객시설, 소득소비 데이터다.
점수가 높을수록 수요 기반이 좋은 상권이다.

2. 매출 성장성
최근 분기 또는 연도별 추정매출 흐름을 평가한다.
활용 데이터는 서울시 상권분석서비스 추정매출 데이터다.
최근 매출 증가율, 매출건수 증가율, 시간대별 매출 패턴, 요일별 매출 패턴을 반영한다.

3. 경쟁 강도
동일 업종 점포가 얼마나 많고, 경쟁이 얼마나 심한지 평가한다.
활용 데이터는 점포-상권 데이터와 소상공인시장진흥공단 상가정보다.
동일 업종 점포 수, 유사 업종 점포 수, 개업 점포 수, 프랜차이즈 점포 수, 반경 300m/500m/1km 내 경쟁점 수를 반영한다.
점수가 높을수록 경쟁이 강하다는 의미이므로, 화면에서는 “주의” 성격의 점수로 표시한다.

4. 유동인구 적합도
선택 업종과 상권의 유동인구 패턴이 잘 맞는지 평가한다.
활용 데이터는 길단위인구, 상주인구, 직장인구 데이터다.
시간대별 유동인구, 성별·연령대별 유동인구, 직장인구 비중, 상주인구 비중을 반영한다.

5. 점포 생태계 안정성
개업과 폐업 흐름을 기준으로 상권 내 점포 생태계가 안정적인지 평가한다.
활용 데이터는 점포-상권 데이터와 상권변화지표 데이터다.
개업 점포 수, 폐업 점포 수, 폐업률 proxy, 운영 영업 개월 평균, 폐업 영업 개월 평균, 상권변화지표를 반영한다.

6. 업종 생존성
선택 업종이 통계적으로 얼마나 오래 생존하는지 평가한다.
활용 데이터는 KOSIS 기업생멸행정통계다.
산업별 신생기업 생존율, 시도별·산업대분류별 생존율, 종사자규모별 생존율을 반영한다.

7. 임대료·고정비 부담
해당 지역에서 임대료와 부동산 비용 부담이 큰지 평가한다.
활용 데이터는 한국부동산원 상업용부동산 임대동향, 국토교통부 상업업무용 실거래가 데이터다.
임대가격지수, 임대료 추세, 지역별 상업용 부동산 가격 흐름을 반영한다.
점수가 높을수록 부담이 크다는 의미로 표시한다.

8. 부채 체력
사용자가 입력한 대출잔액, 금리, 월 상환액, 현금보유액, 월매출, 고정비를 기준으로 재무적으로 얼마나 버틸 수 있는지 평가한다.
활용 데이터는 사용자 입력값 또는 합성 점포 데이터다.
이자부담률, 고정비부담률, 부채상환부담률, 현금보유개월 수, 매출 10% 감소 시 생존기간, 매출 20% 감소 시 생존기간을 반영한다.

셋째, 신한 서비스 연결 점수다.
이 점수는 직접 상품 추천이 아니라, 상담 또는 점검 필요성을 보여주는 용도로 사용한다.

1. 신한은행 금융 점검 필요성
필요자금, 손익분기점, 대출잔액, 금리, 월 상환액, 현금보유개월 수를 기준으로 산출한다.
점수가 높으면 “자금 구조 점검 필요”, “운영자금 상담 검토”, “정책자금 확인 필요” 같은 문구를 보여준다.

2. 신한카드 매출관리 활용도
매출건수, 객단가, 시간대별 매출 편차, 요일별 매출 편차, 경쟁점 밀도, 재방문 전략 필요성을 기준으로 산출한다.
점수가 높으면 “가맹점 매출관리 리포트 활용”, “카드 프로모션 검토”, “재방문 고객 쿠폰 전략” 같은 문구를 보여준다.

3. 신한라이프/보험 점검 필요성
업종 리스크, 방문 고객 수, 점포 규모, 화재·배상책임 가능성, 휴업손실 위험을 기준으로 산출한다.
점수가 높으면 “사업장 화재보험 점검”, “배상책임보험 점검”, “휴업손실 보장 검토” 같은 문구를 보여준다.

4. 신한투자증권/성장지원 가능성
매출 안정성, 부채 부담 낮음, 상권 성장성, 업종 생존성, 다점포 확장 가능성을 기준으로 산출한다.
점수가 높으면 “법인 전환 상담”, “성장지원 검토”, “B2B 제휴 연결”, “프랜차이즈 확장 검토” 같은 문구를 보여준다.

최종 종합점수는 사용자 유형에 따라 가중치를 다르게 적용한다.

28. 최종 서비스 정의

이 서비스는 단순 상권조회나 챗봇이 아니라, 공공데이터 기반 상권 분석을 출발점으로 자영업자의 창업·운영·자금·보험·카드·성장지원까지 연결하는 신한금융그룹형 One-Stop 경영 컨설팅 웹서비스다.
